# Agent Execution Rules

**Classification:** AUTHORITATIVE

1. Read `MASTER_PROJECT_BLUEPRINT.md`, this file, the active DA/KS roadmap item, applicable
   ADRs, code, tests, and Git status before acting.
2. Implement one roadmap item only. Never implement a future item “while here.”
3. Preserve unrelated and uncommitted work; report it explicitly.
4. Reuse canonical lifecycle terms and shared contracts. Do not add another status enum
   without an accepted decision.
5. Code/tests are implementation evidence; reports alone are not.
6. Never infer or approve copyright, public-domain status, source trust, human review,
   risk acceptance, production readiness, or publication.
7. Never generate production embeddings, publish collections, or alter production data
   without explicit authorization and satisfied gates.
8. Research-agent output is untrusted discovery data and always enters registration.
9. Preserve Marifetname-first routing and all adult/self-report, medical, biometric,
   third-party, child, fate, citation, privacy, and source-insufficiency boundaries.
10. Do not let DA runtime read KS work queues or local source files.
11. Report created/modified files, tests, acceptance criteria, limitations, Git status,
    and skipped checks.

Stop for human approval when legal/source approval, risk acceptance, model/provider
selection, reviewer assignment, production publication, store submission, secrets,
destructive migration, or a conflict in authoritative decisions is required.
