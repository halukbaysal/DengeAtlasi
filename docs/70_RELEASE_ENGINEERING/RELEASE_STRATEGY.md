# Release Strategy

**Classification:** AUTHORITATIVE

## Denge Atlası application release

Requires reproducible mobile/API builds, contract and regression suites, device,
accessibility and performance evidence, vulnerability/security review, human red-team,
privacy/store disclosures, signing authority, deployment/monitoring/incident readiness,
and binary/backend rollback.

## Knowledge corpus publication

Requires exact source legality, OCR/subject/safety/chunk decisions, pinned embeddings,
candidate collection integrity, Phase B evaluation, publication authority, immutable
manifest, protected snapshot/backup, isolated restore, rollback test, and monitoring.

## Shared controls

Both use change review, least privilege, provenance, signed/versioned artifacts,
vulnerability register, secrets management, logs without prohibited data, incident
runbooks, human approval, and post-release verification. A blocked corpus does not
automatically block a source-free DA build; an approved corpus does not approve the app,
deployment, signing, or stores.
