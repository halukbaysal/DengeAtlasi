# Sprint 01 — Engineering Foundation

## Goal

Create a clean, testable monorepo foundation containing the React Native CLI mobile app, FastAPI backend, OpenAPI contract workflow, shared development commands, and CI quality gates.

## Why Now

Every later sprint depends on stable mobile and backend foundations. This sprint creates only the engineering skeleton and proves both sides can build and communicate through a versioned contract.

## Architecture Constraints

- No Expo.
- FastAPI is the backend framework.
- OpenAPI is the contract source.
- Mobile types must not be manually duplicated when generated types are available.
- No provider SDK integration.
- No production secrets.
- SQLite shell must not implement Sprint 07 features.
- The backend health endpoint must not depend on external AI services.

## Implementation Tasks

1. Create canonical repo structure:
   ```text
   apps/mobile
   services/api
   packages/api-client
   docs
   scripts
   tests
   ```
2. Initialize React Native CLI with TypeScript.
3. Configure React Navigation shell with a minimal placeholder home screen.
4. Add Zustand and create a minimal typed app store.
5. Add Zod and a sample health-response schema.
6. Add SQLite dependency and a database initialization abstraction only.
7. Initialize FastAPI with Pydantic settings.
8. Implement `GET /health`.
9. Add backend tests for `/health`.
10. Generate OpenAPI JSON.
11. Generate or script generation of TypeScript API types/client.
12. Add a mobile test validating the health response schema.
13. Add backend Dockerfile and local run instructions.
14. Add `.env.example` files with no secrets.
15. Add lint, typecheck, test, OpenAPI generation, and build scripts.
16. Add CI that runs available quality gates.
17. Document exact setup and run commands.

## Acceptance Criteria

- Clean install succeeds.
- Mobile TypeScript project builds or typechecks successfully.
- Android project is generated and valid.
- iOS project is generated and valid when run on macOS.
- FastAPI starts locally.
- `GET /health` returns structured JSON containing status, service, version, and timestamp.
- Backend tests pass.
- OpenAPI schema can be generated by a documented command.
- TypeScript API types/client can be generated by a documented command.
- Mobile validates the health response with Zod.
- Zustand is configured without domain features.
- SQLite initialization shell exists without journal tables beyond a migration/version mechanism if needed.
- Docker image for the backend builds.
- CI configuration exists and runs relevant checks.
- No future sprint feature is implemented.

## Required Tests

- Backend `/health` unit/integration test
- Pydantic response-model validation
- OpenAPI generation test or snapshot check
- Generated TypeScript contract compilation
- Mobile Zod health-schema test
- Zustand store smoke test
- SQLite initialization smoke test
- Root command smoke checks

## Manual Testing Steps

1. Install dependencies from a clean checkout.
2. Start the FastAPI backend.
3. Open `/health` in a browser or `curl`.
4. Generate OpenAPI.
5. Generate TypeScript API types.
6. Run backend tests.
7. Run mobile tests.
8. Run mobile typecheck.
9. Build or launch Android.
10. Build or launch iOS when on macOS.
11. Build the backend Docker image.
12. Verify no secrets are committed.

## Known Risks

- React Native native toolchain differences across machines.
- Generated API client tool choice may require a small dependency.
- iOS build cannot run outside macOS and must be reported honestly.
